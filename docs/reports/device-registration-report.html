Summary

Any app calling for the first time with an unknown MAC gets a device record, a 6-digit device key and a trial (7 days by default, settable per brand). That record lives in pendingDevices. It moves into devices only when the device pays, inside a MongoDB transaction. Unpaid devices are never removed, so a device can't get a second trial by coming back later.

The old apps don't change. Each brand answers in the exact shapes its old backend used (key order, field types, encodings). That means the V4 API, the legacy TV playlist_info, signed Android, Roku and the iOS/Android v2–v3 logins all work.

The work was done in five slices:

  • 1. Devices module. Pending or paid, trial length, unique key, and the move on payment.
  • 2. Legacy codecs. Envelope, CryptoJS AES, HMAC signatures and the XOR token.
  • 3. V4 API. Captcha, device_login and device_info.
  • 4. Devices without a usable MAC. These are identified by app_device_id.
  • 5. Pre-V4 app routes, answered with per-brand response shapes.

Architecture

Domain

The Device entity: pending or paid, trial end, key, uid, appUid, appDeviceId. Value objects: TrialDays, AppType, Uid, AppDeviceId, LegacyProfile. Typed errors.

Application

Ports: repository, key generator, settings, captcha store and images, random MAC. Seven use cases with no framework or database code.

Infrastructure

Mongo repository (two collections, transactional move), settings in tenantConfig, a captcha store with a 300 s TTL, svg-captcha, and migrations 0001–0003.

Interfaces

Legacy codecs, the V4 controller, the old-apps controller, presenters (pure functions checked against recorded responses), CLI commands.

  • loose request bodies are handled safely;
  • brands stay isolated;
  • the race handling for concurrent first requests and concurrent activation is sound.

Decisions I made

  • Trial length lives in each brand's tenantConfig and is read on every new device. A bad stored value falls back to 7 with a warning.
  • Requests in the envelope are decoded as Latin-1, as the apps really send them. AES is reimplemented on node:crypto and is proven compatible with CryptoJS.
  • An unknown V4 {type} returns 404, and an undecodable envelope returns 400. The old code fell back or sent garbage.
  • Paid devices show is_trial 2 (lifetime) until licences exist. is_expired stays false, as in all the old backends.
  • One global LEGACY_TOKEN_KEY and one set of Android secrets until per-brand secrets exist (TEN-04).
  • The fallback MACs 52:54:00:12:34:56/57/59 count as "no MAC". Such devices get a random locally administered MAC.
  • The per-brand legacy profile picks the response shapes. tmdb_api_key is sent empty, because the old hard-coded key was not copied.
  • No app-update fields. Playlists are empty or the demo entry until the playlists module exists.
  • A device first registered by another app family adopts the iOS/Android install uid instead of being refused forever.
  • The CR Android v2/v3 captcha, the per-family V3/V4 locks, and the signed TV V3 and Android V3 routes are not reproduced.
